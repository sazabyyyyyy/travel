# 旅程作成

新しい旅を、行き先に合った装いのしおりとして作り、GitHub Pages まで公開する。

伊根ページ（`ine/index.html`）は情報設計の見本である。見た目のコピー元ではない。舟屋・和紙・青海波は伊根用であり、別の旅に使い回さない。

必須セクションは必ず必須でなくてもいいし、順序や構成も都度変更していい。ただし AI とすぐわかるようなデザインは避けること。

## 完了条件

- [ ] `{slug}/index.html` がある
- [ ] 装いが行き先の空気に合っている（AI くさい見た目になっていない）
- [ ] ルート座標は実ルート（推測で線を引かない）
- [ ] 目次 `index.html` と `README.md` に登録済み
- [ ] ブラウザで目次と新規ページを確認済み
- [ ] `main` に push 済み
- [ ] 公開URLをユーザーに渡済み

ユーザーが「公開しない」「コミットしない」と言った場合だけ、デプロイを止める。

## ワークフロー

進めながらチェックする。

```
- [ ] 1. 条件を揃える
- [ ] 2. 旅程を立てる
- [ ] 3. 装いを決める
- [ ] 4. ページを作る
- [ ] 5. 目次へ登録する
- [ ] 6. ブラウザで確かめる
- [ ] 7. デプロイする
```

### 1. 条件を揃える

足りないものだけ聞く。推測で日程や便名を確定させない。

必須: 出発地、行き先、泊数、重視すること（景色 / 食事 / 体験 / のんびり など）

あると精度が上がる: 日付、人数、交通の希望、宿の希望、避けたいこと

日付が未定なら時刻は目安と明記する。

フォルダ名は英小文字とハイフン（例: `ine`, `nara-2nights`）。タイトルは日本語。

### 2. 旅程を立てる

移動時間に余白を残す。初日と最終日は移動で削れる前提で組む。

調べる:

- 空港・駅・所要時間・乗り継ぎ
- 営業時間、予約の要否、定休日
- 現地のマナーや注意（私有地、混雑、天候運休）

場所の座標は Nominatim 等で実在の点を取る。存在しない店名・便名を作らない。

道路ルートはスキル内スクリプトで取る。手順は [page-contract.md](page-contract.md) を読む。

### 3. 装いを決める

コードを書く前に、短いデザインメモを自分用に置く（ユーザーへの長文説明は不要）。

決めること:

- 空気（例: 雪国の藍、南の浅瀬、古い城下町、近代港町）
- 色 5〜7（地、墨、Muted、線、海や空に当たる色、日ごとの 2〜4 色）
- 見出し用と本文用のフォント（Google Fonts 可）
- 飾り 1 系統だけ（波、格子、石垣、雪輪など）。伊根の屋根・青海波を默认にしない
- 地図タイル: 国内は国土地理院の淡色。国外は OSM / Carto
- AI くさい見た目を避ける。紫〜ティールのグラデ、ガラス、ネオン、同じ角丸カードの均等グリッド、スタートアップ LP 風の汎用サンセリフ、のっぺりした生成画、絵文字やキラキラアイコンの羅列は使わない

目次ページ（`index.html`）の装いはサイト共通の「本」として維持する。旅ごとの世界観は各しおり側で出す。カードの文言と写真だけ足す。

### 4. ページを作る

使える部品と JS のデータ形は [page-contract.md](page-contract.md)。部品の採否・順序・構成は旅に合わせて変える。

- 新規フォルダ `{slug}/` に `index.html` と必要なら `images/`
- 挿絵を置くなら行き先の景色。`GenerateImage` を使ってよいが、プラスチック光沢や左右対称の生成画にしない。写真素材を捏造キャプションしない
- 地図を置くなら Leaflet。日フィルタ、日程クリックで該当地点へ飛ぶ
- 「地図を開く」は Google Maps の経路リンク
- 注意（予約、乗り捨て、天候、マナー）が必要なら、その旅に合う場所へ書く
- 時刻が目安なら、出発日が決まったら便と営業時間を確認する旨をどこかに書く

### 5. 目次へ登録する

`index.html` の `.trips` にカードを追加する。

- 見出し、一文の要約、スタンプ 2〜4、挿絵 2
- `href="{slug}/"`
- 既存カードのマークアップを踏襲する（目次の装いは変えない）

`README.md` の表にも 1 行足す。

### 6. ブラウザで確かめる

見た目のスクショ 1 枚では足りない。

1. ローカルサーバ: `python3 -m http.server 8765`
2. 目次 → 新規しおりへ遷移
3. 置いた操作（日フィルタ、日程クリック、地図リンクなど）が動くこと
4. 初日・最終日など端の状態
5. デスクトップと狭い幅
6. 既存の伊根ページが壊れていないこと

問題があれば直して再確認する。

### 7. デプロイする

公開は `main` のルートを GitHub Pages が見る。

```
https://sazabyyyyyy.github.io/travel/{slug}/
```

1. 旅程関連だけを stage する（`.env` 等は入れない）
2. コミット文は日本語で「なぜ」を 1〜2 文。既存ログに合わせ、体言止めより説明文
3. `git push -u origin HEAD`
4. `gh api repos/sazabyyyyyy/travel/pages` で `status` を見る。`errored` なら直す
5. 公開URLを返す。必要なら数分待って live も開く

force push はしない。

## やらないこと

- 伊根の CSS を色だけ変えて使い回す
- 伊根と同じセクション順を、中身に関係なく守る
- AI とすぐわかるようなデザイン
- 座標や道路を感覚で描く
- 便名、料金、営業時間を根拠なく断定する
- 目次の全体テーマを旅ごとに塗り替える
- ユーザーが止めたあとに push する
